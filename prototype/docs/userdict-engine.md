# 使用者詞庫：引擎實作說明

規格（檔案格式、協定、選字規則）在 `crates/docs/userdict-handoff.md`。
這份文件說明 Python 原型怎麼實作，Rust 引擎照同樣的做法移植，結果才會一致。
程式在 `prototype/bopogram/`：`userdict.py`（檔案）、`lexicon.py`（查詢）、`decoder.py`（解碼）、
`dictops.py`（協定操作）、`session.py`（何時重新解碼）。

## 檔案

- 讀檔時略過 BOM、空行、`#` 開頭的行；壞行只在 stderr 記「檔名: line N skipped」，不記內容。
- 讀音檢查只看注音結構：`[˙] [聲母] [介音] [韻母] [ˊˇˋ]`，至少一個符號；
  輕聲不能再帶聲調；只有一個聲母時，必須是 ㄓㄔㄕㄖㄗㄘㄙ。不要求音節出現在字典裡。
- 每次修改先在記憶體外產生新內容，寫入 `.tmp` 並取代原檔**成功後**才換掉記憶體中的資料。
  寫入失敗回 `reason: "write_failed"`，詞庫維持原狀。
- `excluded.tsv` 裡同一段文字有「全部讀音」那一行時，個別讀音的行一併移除。

## 查詢（字典上面的一層）

- 字典本身不動。使用者詞與排除清單是另一層，詞庫有變動時整層重建，並讓 `version` 加一。
- `candidates(音節)`：使用者詞在前，接著字典詞（去掉重複），再去掉「含有被排除文字」的詞。
  「含有」的判斷：詞中任一段等於某個被排除的文字，而且那段的音節符合（或該排除不限讀音）。
- 解碼時「語言模型不認得的詞先剔除」與「每個讀音最多 40 個候選」這兩條規則都不套用到使用者詞。
- 使用者詞每條邊加 `user_dict_bonus`（預設 6.0：300 個隨機兩到四字的使用者詞，沒有上文時 299 個首選就是它，剩下 1 個輸給另一個同音的使用者詞；同時 12,170 句評估句只有 2 句改變）。語言模型不認得的詞照常由模型給未知詞的分數。
- 候選清單（`candidates` 操作）在同一長度內使用者詞排第一。
- 句尾機率（`eos_weight`）：路徑最後一個詞是使用者詞時不扣句尾分數。使用者詞對模型是未知詞，
  模型會以為「未知詞後面結束句子」很少見，使用者詞不應該因此輸掉。
- 字級模型（charlm）重新排序時，只能在**保留 n-gram 首選裡全部使用者詞（同位置、同一個詞）** 的結果之間挑選。
  字級模型不認得使用者詞；不加這條，實測 300 個隨機使用者詞有 5 個被它換掉。

## 排除：跨詞也保證不會自動選出

每條路徑（Hyp）多記一個字串 `tail`：路徑文字的結尾中，**最長且是某個被排除文字的「真前綴」** 的那一段
（真前綴：長度 1 到全長減 1）。沒有就是空字串。

把詞 `w`（從第 `i` 個位置開始）接到路徑後面時：

1. `text = tail + w`，`text` 的第一個字在位置 `i - len(tail)`。
2. 對 `text` 中每個**結束在 `w` 裡面**的位置，檢查以它結尾、長度為各個排除文字長度的那一段：
   若等於某個被排除的文字，而且音節符合（或不限讀音），這條延伸就丟掉；
   **例外**：那一段的每個位置都在使用者手選的範圍（pinned span）內，就放行。
3. 新的 `tail` 是 `text` 結尾中最長的、屬於「真前綴集合」的那一段（最多 `MAX_WORD_LEN - 1` 個字）。

正確性：任何跨進 `w` 的排除文字，它在 `w` 之前的部分一定是某個排除文字的真前綴，
而且是路徑結尾，所以一定落在 `tail` 裡（與 Aho–Corasick 的失敗連結同理）。

合併：原本「語言模型狀態相同就合併」改成「語言模型狀態與 `tail` 都相同才合併」。
排除清單是空的時候 `tail` 永遠是空字串，解碼結果與沒有這個功能時完全相同。

某個位置所有路徑都被擋掉時，沿用既有的備援：該音節以注音原樣顯示（不可能含有被排除的文字）。

## 何時套用新的詞庫

協定操作只更新詞庫，不重新解碼任何組字區（畫面不會突然變動）。
每個解碼器記得自己是用哪個 `version` 建的；版本不同時，下一個會改變或送出組字區的操作
（輸入音節或符號、退格、刪除、選字、`cycle`、`commit`）先把**整個**組字區重新解碼一次，再做該操作。
只重算新的位置不夠：前面已經算好的部分可能含有剛被排除的文字。

## 個人化學習

- 送出時，含有被排除文字的詞不學。
- 刪除或排除時，從 `user.json` 刪掉文字含有它的單詞紀錄，以及兩個詞接起來含有它的雙詞紀錄，並立即存檔。

## 其他判斷

- `dict_remove` 一個同時在使用者詞庫與字典裡的詞：兩邊都處理（移出使用者詞庫，並排除字典的詞），回 `removed: "excluded"`。
  先做排除；排除被拒（`last_candidate`）時使用者詞庫不動。
- `last_candidate` 只會發生在排除單一個字時：檢查那個字的每個（或指定的）讀音，排除後是否還有其他候選。
- `readings`：整個詞在字典或使用者詞庫裡時，只列它的讀音，依各字讀音機率的總和排序；
  被排除的讀音 `known: false`。不在字典裡時逐字組合，以 beam 保留前 16 個，`known` 一律 false；
  有字查不到任何讀音時回空清單。
- `dict_add` 帶 `start`／`length` 時，範圍內有符號或沒轉換的注音回 `bad_reading`；範圍超出組字區回 `not_found`。
